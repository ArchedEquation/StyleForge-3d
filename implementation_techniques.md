# StyleForge 3D: Implementation Techniques

This document outlines the core technical methodologies used in the StyleForge 3D pipeline to achieve automated 3D model stylization.

## 1. Pipeline Architecture
The system is built as a **FastAPI** microservice that orchestrates a linear pipeline. To ensure modularity and stability, heavy processing tasks are decoupled from the API worker:
- **Geometry Processing** and **Style Transfer** run as separate Python processes.
- This prevents the web server from blocking during intensive numeric operations.
- We successfully migrated from a *Blender-dependent* workflow to a **Python-native** workflow to ease deployment and reduce overhead.

## 2. Geometry Processing (Python-Native)
Instead of relying on a headless Blender instance, we utilized specialized Python libraries to handle mesh operations directly.

### A. UV Unwrapping with `xatlas`
We use **[xatlas](https://github.com/jpcy/xatlas)**, a wrapper for the robust UV unwrapping library used in game engines.
- **Charts & Atlases**: It automatically segments the mesh into "charts" (islands) to minimize distortion.
- **Seam Handling**: `trimesh` is configured with `process=False` upon reloading to ensure that the split vertices generated by `xatlas` (to create UV seams) are preserved. If vertices were merged, the texture mapping would collapse at the seams.

### B. Structure Baking (Ambient Occlusion / Normals)
To give the Neural Style Transfer a "structure" to latch onto, we generate a **Content Map**.
- **Normals-to-Texture**: We map the vertex normals to the UV space. This encodes the geometry's curvature and edges into color data.
- **Interpolation**: We use `scipy.interpolate.griddata` to rasterize these vertex values into a 2D pixel grid based on the UV coordinates. This creates a smooth gradient map representing the 3D form in 2D space.

## 3. Neural Style Transfer (NST)
We implemented a custom **PyTorch** module based on the Gatys et al. optimization method, refined for texture generation.

### A. Loss Function Engineering
- **Content Loss**: Calculated at deep layers (`conv_4`) of VGG19. This ensures the *semantic structure* (shapes, edges from the normal map) is preserved, rather than exact pixel values.
- **Style Loss**: Calculated across multiple scales (`conv_1` to `conv_5`) using Gram Matrices. This captures the "texture" (brush strokes, color palette) of the style image.
- **Total Variation (TV) Loss**: Added to penalize high-frequency noise. This is critical for UV textures to prevent "pixel snow" and ensure smoother transitions across the model surface.

### B. Optimization Strategy
- **Initialization**: We initialize the optimization with the **Content Map** (not random noise). This drastically improves structure preservation and convergence speed.
- **Optimizer**: We use **LBFGS** (Limited-memory BFGS), a quasi-Newton method. It consumes more memory than Adam but typically converges to a sharper, higher-quality result in fewer iterations for style transfer tasks.
- **Weight Balancing**: weights were carefully tuned (`Style: 1e5`, `Content: 50`) so the geometry doesn't get "washed out" by the style.

## 4. Asset Packing
The final step involves re-assembling the 3D file.
- We use **`trimesh`** to load the processed geometry (with UVs).
- We create a **PBR Material** pointing to the newly generated stylized image.
- The result is exported as a binary **.glb** (glTF 2.0), which embeds the texture and geometry into a single, portable file ready for web viewers.
